Smart Lawn

Coming soon Concept & planning

An idea for understanding how my lawn behaves — then using that information to make watering more considered.

01 / THE IDEA

Measure first. Automate later.

I currently water the lawn manually. Parts of it receive different amounts of sun and shade, so I want to compare moisture and soil temperature in three locations rather than rely on a single reading.

The concept connects three buried moisture probes and dedicated PT100 temperature sensing to one ESP32-S3 controller and a web dashboard. The first irrigation experiment would use one valve and sprinkler. Three measurement zones do not mean three independently watered zones.

THE QUESTION BEHIND THE PROJECT

What happens beneath the grass?

I want to understand how the same small lawn behaves differently in sun and shade. The most useful result would be a record of the soil over time, with watering decisions that can be traced back to measurements.

  • Compare how quickly each location dries after watering.
  • Follow soil temperature changes during the day and across seasons.
  • Observe how long a moisture change takes to reach each probe.
  • Identify which location loses moisture first.
  • Explore seasonal and year-long comparisons once enough data has been collected.
  • Measure water use if a flow meter is added later.

The proposed direction is local operation, modular hardware and software I can adapt. An open-source release is an option to consider once the prototype and documentation exist.

04 / DASHBOARD STUDY

See the differences over time.

A planned web interface would show moisture, soil temperature, measurement freshness and comparisons between the three zones. Historical trends would help evaluate watering and recovery.

C++ firmware, Wi-Fi, RS485 and a React dashboard are proposed directions. The final software stack has not been selected.

05 / PLANNED NEXT STEPS

A prototype in stages.

  1. Select and test one probe. Confirm communication, repeatable readings and calibration in the actual soil.
  2. Build the first dashboard. Display readings and their age, then record trends and add the other monitoring zones.
  3. Test one valve manually. Check control, shut-off behaviour and a maximum watering duration before enabling automatic operation.
  4. Evaluate automation. Validate sensor fault handling and watering rules; consider weather data, a flow meter and additional valves later.

This is a future project, with no completed controller, field trials or release yet. My next step is choosing a small first prototype that I can test and learn from.
