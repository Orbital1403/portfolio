<h2 id="applying-these-skills-in-personal-projects"><TopicIcon name="projects" heading />Applying these skills in personal projects</h2>

### <TopicIcon name="audio" heading />MILA — audio streamer

I define requirements and expected behaviour, investigate problems, check installed versions on the device and decide which changes are acceptable. One example is handling a command when its response never arrives. The player may already have performed the action, so the system needs to communicate the uncertain outcome and avoid an unintended repeat.

[Explore MILA →](/projects/mila/)

### <TopicIcon name="garden" heading />grgaGrow — garden application

I shape how readings, history and alerts are presented, and check missing or stale data. On the bench, one ESP32 controller read both probes on one RS485 bus and sent the first samples to the cloud, which acknowledged them. Calibration and continuous outdoor monitoring on the lawn remain unverified.

[Explore grgaGrow →](/projects/grgagrow/)

### <TopicIcon name="laundry" heading />Our laundry — shared laundry application

I define machine states and the resident workflow, and check how the interface handles uncertain or outdated information. A finished cycle, an open door and an available machine are treated as separate facts. The public demo uses simulated states; live integration and recovery checks remain in development.

[Explore Our laundry →](/projects/our-laundry/)

### <TopicIcon name="code" heading />How I work on projects

I define the problem, decide how the product should behave, verify the results and decide which changes to accept. Through this process, I also develop my understanding of the code and the system.
